# Sustainable plan design and longitudinal fatigue

Load when an athlete is "always tired", reports repeated poor sessions, or is
frustrated that the plan changes every week. Breathlessness or long-term
decline: `references/running-plateau-and-breathlessness.md`.

## Interpretation

- Recurring subjective fatigue is a plan-design signal even when sleep, HRV,
  resting HR, nutrition and medical values look normal — normal markers make a
  design mismatch *more* likely. Do not diagnose overtraining from TSB alone.
- The athlete should not have to renegotiate the plan every week: adaptation
  belongs in the plan, not in repeated same-day substitutions. Do not frame
  fatigue as a motivation problem.
- A recovery block that already produced positive TSB is evidence against
  modelled load as the sole cause, not a reason to extend rest indefinitely.

## Load review (actual vs planned)

1. Reconcile the data first: deduplicate uploads, separate planned from
   completed sessions, check sport labels. When the athlete says the log is
   wrong (e.g. intervals shown that never happened), their account of
   completed sessions is authoritative.
2. Review 6–12 weeks: CTL ramp, ATL peaks, consecutive negative-TSB days,
   hard-session density, actual vs planned load.
3. Wellness CTL/ATL/TSB may be sport-scoped or mislabelled; reconcile with
   sport-specific activities before attributing load to running or cycling.
4. If a stats query fails, say which data you actually have; do not imply a
   precise aggregate. Retry with corrected parameters.

## Plan design response

Default stable rebuild block, designed to run largely unchanged:

1. Baseline below the recent peak load.
2. One key intensity session per week; a second only after several stable
   weeks.
3. Long run easy and non-progressive while rebuilding.
4. ≥ 48 h between hard sessions; rest days named in the plan table (calendar
   left empty).
5. Deload every 3rd week (sooner if the trend warrants) — not an aggressive
   block followed by a distant recovery week.
6. Never raise volume, intensity and strength at the same time.
7. Present the complete revised block as a table before changing calendar
   events.
